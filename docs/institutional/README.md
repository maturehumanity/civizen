# Institutional Architecture

Working institutional architecture for Civizen — proposed structures, not formed legal entities.

These documents are **project reference** materials. They are not the public institutional policy pack and are not published as primary in-app `/documents` pages.

### Institutional Architecture

| Document | Status | Notes |
| --- | --- | --- |
| [`institutional-blueprint.md`](./institutional-blueprint.md) | Working Institutional Blueprint (draft 0.1) | **What** Civizen's institutions, bodies, entities, and major relationships are |
| [`governance-framework.md`](./governance-framework.md) | Working Governance Framework (draft 0.1) | **How** authority is distributed and exercised among those institutions — subordinate to the Blueprint; do not merge |
| [`stakeholder-partnership-framework.md`](./stakeholder-partnership-framework.md) | Working Stakeholder & Partnership Framework (draft 0.1) | **Who** Civizen engages; multi-dimensional classification; partnership roles and modules; Contribution Record for partners; future Stakeholder Map — subordinate to the Blueprint; consistent with the Governance Framework |
| [`pilot-framework.md`](./pilot-framework.md) | Working Pilot Framework (draft 0.1) | **What** Civizen tests and implements with those participants, how pilots operate, and how evidence is evaluated — subordinate to the Blueprint; consistent with Governance and Stakeholder & Partnership Frameworks |
| [`founder-transition-succession-framework.md`](./founder-transition-succession-framework.md) | Working Founder Transition & Succession Framework (draft 0.1) | How founder authority, access, stewardship, and succession should evolve — specialized implementation of Blueprint §§6.2/15 and Governance Framework §7; functional self-sufficiency, not automatic access removal; do not merge |
| [`contributor-framework.md`](./contributor-framework.md) | Working Contributor Framework (draft 0.1) | Contribution Record design, evidence, validation, recognition, responsibility, opportunity — not public policy; `/contribute/policy` remains [`../02-policies/institutional/contributor-participation-and-recognition.md`](../02-policies/institutional/contributor-participation-and-recognition.md) |
| [`areas-domains-participation-framework.md`](./areas-domains-participation-framework.md) | Working Areas, Domains & Participation Framework (draft 0.1) | Shared Area / Domain / Topic / Initiative / Role taxonomy; semantic support for Areas & Pilots Catalog — Catalog not built; minimal public `/areas` V1 is separate |

The Stakeholder & Partnership Framework consolidates Stakeholder Map, Partnership Strategy, Partnership Framework, and Partnership Packages. Do not create competing parent documents for those names. Public `/partners` copy remains [`../02-policies/institutional/international-partnerships-and-chapters.md`](../02-policies/institutional/international-partnerships-and-chapters.md). The Pilot Framework is the parent for concrete pilot/validation plans; those operational children remain in place. The Founder Transition & Succession Framework elaborates founder authority and continuity; it does not change current founder bootstrap access. The Contributor Framework is the parent for Contribution Record *design*; adopted public contributor policy remains `/contribute/policy`. Doc `21` is compensation planning, not that Framework. The Areas, Domains & Participation Framework is the parent for shared taxonomy (**current foundational Area model**; evolvable). It does not replace product `PILLARS` until a later mapping task. Shared classification evolution: [`../03-platform/model-evolution/shared-classification-and-model-evolution-architecture.md`](../03-platform/model-evolution/shared-classification-and-model-evolution-architecture.md) (platform architecture; not item 8).
